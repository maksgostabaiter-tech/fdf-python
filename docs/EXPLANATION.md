# Алгоритмы и устройство программы

## Входные данные и модель
Строка файла задаёт координату y, номер значения — x, само число — высоту z. Координаты начинаются с нуля. Карта elem.fdf содержит 5 строк по 5 значений; её центральная точка имеет координаты Point(2, 2, 5).

Парсер parse_map читает файл, отбрасывает пустые строки в конце и проверяет прямоугольность. parse_value проверяет целую высоту и необязательный цвет. Например, 1,0xff превращается в высоту 1 и цвет #0000FF. Ошибка формата вызывает MapFormatError с номером строки и значения. Ошибка доступа к файлу передаётся как OSError.

Point хранит x, y, z, color. Map хранит прямоугольную сетку. Метод neighbors(x, y) возвращает правого и нижнего соседей, поэтому геометрические рёбра не дублируются.

## Изометрическая проекция
Для стандартного угла 30 градусов используются формулы задания:

```text
x′ = (x − y) × cos(30°)
y′ = (x + y) × sin(30°) − z × z_scale
X = x′ × scale + offset_x
Y = y′ × scale + offset_y
```

Ось Y экрана направлена вниз, поэтому положительная высота вычитается. По умолчанию z_scale = 1. Точка (2, 2, 5) до масштабирования переходит в (0, −3).

Camera.fit находит границы всех спроецированных точек и выбирает меньший из допустимых масштабов по ширине и высоте с коэффициентом 0,9. Затем центр границ совмещается с центром окна. Для одной точки деления на ноль нет: выбирается scale = 1, точка располагается в центре.

## Отрисовка
App переводит точки в экранные координаты и соединяет каждую с соседями справа и снизу. Для сетки W×H число рёбер равно H×(W−1) + W×(H−1). Для 5×5 это 40 рёбер. Разноцветное ребро делится на 12 отрезков для приближения градиента.

# Основы Python для чтения кода

## Что происходит при запуске
Python — язык программирования. Интерпретатор Python выполняет инструкции из .py-файлов. Команда python main.py maps/elem.fdf означает: выполнить main.py и передать ему строку maps/elem.fdf. Эта строка — аргумент командной строки.

Модуль — отдельный .py-файл. Пакет fdf — папка с модулями и файлом __init__.py. Импорт позволяет использовать определённые в другом модуле функции и классы.

## Минимальный словарь

| Запись | Простое объяснение |
| --- | --- |
| x = 2 | Сохранить значение 2 под именем x |
| str / int / float / None | Строка / целое / дробное / отсутствие значения |
| list / tuple | Последовательность; кортеж нельзя менять на месте |
| def | Определить функцию |
| return | Вернуть результат и закончить функцию |
| if / else и for | Выбор действия по условию и цикл |
| class | Описать новый тип объектов |
| self | Текущий объект внутри его метода |

В Python отступы определяют, какие строки относятся к циклу, условию или функции. Их нельзя убирать произвольно.

## Прочитай небольшой пример

```python
for x, token in enumerate(tokens):
    z, color = parse_value(token, y + 1, x + 1)
    row.append(Point(x, y, z, color))
```

enumerate выдаёт номер и элемент: для tokens = ["0", "5"] получаются пары (0, "0") и (1, "5"). parse_value превращает текст в высоту и цвет. Point создаёт объект точки. append добавляет его в текущую строку карты.

## Аннотации и исключения
Запись z: int говорит, что z должен быть целым. Аннотация помогает mypy искать ошибки, но сама по себе не проверяет входной файл при запуске.

raise сообщает об ошибке, возбуждая исключение. try запускает действие, except перехватывает определённую ошибку. Ошибка проходит вверх по вызовам, пока не встретит подходящий except. В нашей программе диагностику формирует main.py.

# Парсер от текста к точкам

Парсер — проверяющий переводчик. На входе у него текст, а на выходе объекты Map и Point, с которыми удобно считать и рисовать.

## Шаги функции parse_map
1. Path(path).read_text читает файл в строку. UTF-8 задаёт кодировку, вариант utf-8-sig также принимает BOM.
2. splitlines разбивает текст на строки. Цикл while убирает пустые строки только с конца.
3. Если строк не осталось, возникает MapFormatError: карта пустая.
4. split разбивает каждую строку на значения и игнорирует повторяющиеся пробелы.
5. Число значений сравнивается с шириной первой строки. Так проверяется прямоугольность.
6. Для каждого значения вызывается parse_value; затем создаётся Point(x, y, z, color).
7. Готовые строки передаются в Map.

Файл «0 1», затем пустая строка, затем «2 3» ошибочен: внутренний пропуск нельзя просто удалить, потому что он изменит координаты строк. Пустые строки после последнего ряда разрешены заданием.

## Как разбирается значение с цветом

```text
token.split(",") → ["2", "0xff"]
int("2")         → 2
int("0xff", 16)  → 255
f"#{255:06X}"    → "#0000FF"
```

Шестнадцатеричная запись использует цифры 0–9 и буквы A–F. Цвет RGB состоит из трёх чисел 0–255: красный, зелёный, синий. В #0000FF синий канал максимальный, остальные нулевые.

Регулярное выражение INTEGER допускает знак и десятичные цифры. COLOR допускает 0x или 0X и от одной до шести шестнадцатеричных цифр. Это не даёт случайно принять дробь, лишнюю запятую или цвет из семи цифр.

## Где ошибка и кто её показывает
В модели координаты начинаются с 0, а для человека строки и колонки считаются с 1. Поэтому в parse_value передаются y + 1 и x + 1. «Колонка 3» здесь означает третье значение, а не третий символ строки.

Парсер возбуждает MapFormatError. main.py перехватывает её через базовый FdfError, печатает сообщение в stderr и возвращает 1. При отсутствии файла возникает OSError; парсер её специально не перехватывает. Поэтому логику чтения можно использовать и в другом интерфейсе.

# Модель Point и Map

Класс задаёт устройство объектов. Point описывает одну точку, Map — всю карту. Объект — конкретный экземпляр класса, например Point(2, 2, 5).

## Зачем dataclass у Point

```python
@dataclass(frozen=True)
class Point:
    x: int
    y: int
    z: int
    color: str | None = None
```

dataclass автоматически создаёт конструктор и сравнение по значениям. frozen=True запрещает обычное присваивание полям после создания. Это защищает координаты от случайных изменений и позволяет использовать Point как ключ словаря в отрисовке. str | None означает: цвет либо строка, либо отсутствует.

## Как устроен Map
В конструктор передаётся список строк с точками. Map проверяет непустую прямоугольную форму и совпадение координат с позициями. Затем копирует данные в кортежи. Ошибка такого ручного создания карты — ValueError: это ошибка использования модели, а не разбора файла.

```python
grid[2][2]       # сначала строка y, потом столбец x
grid.get(2, 2)   # здесь порядок аргументов x, y
len(grid)        # 25 точек для карты 5×5
```

__len__ определяет поведение len. __getitem__ позволяет использовать квадратные скобки. __iter__ задаёт обход всех точек. yield from row по очереди выдаёт элементы строки, а затем переходит к следующей.

## Почему только два соседа
У точки внутри сетки четыре ближайших соседа. Но если каждый раз соединять её со всеми четырьмя, каждое ребро получится дважды. Связь A—B будет нарисована и из A, и из B.

Мы берём только правую и нижнюю точки. У верхнего левого угла это (1, 0) и (0, 1). У нижнего правого угла таких соседей нет. Проверки границ предотвращают выход за пределы карты.

Для карты 5×5 горизонтальных рёбер 5×4 = 20, вертикальных тоже 20. Итого 40 геометрических рёбер. Градиент может разделить одно ребро на 12 цветных отрезков, но это не означает дублирования связей сетки.

# Проекция почему сетка выглядит объёмной

Экран плоский: у него только X и Y. У точки карты есть ещё высота z. Проекция задаёт правило, как из трёх координат получить две. Физического трёхмерного объекта программа не создаёт: она рисует плоские линии, которые выглядят объёмными.

## Сначала без масштаба и сдвига

```text
x′ = (x − y) × cos(angle)
y′ = (x + y) × sin(angle) − z × z_scale
```

angle по умолчанию равен 30°. cos(30°) примерно 0,866, sin(30°) равен 0,5. В коде угол хранится в радианах: 30° = π / 6, потому что функции math.cos и math.sin принимают радианы.

Если увеличить только x, точка пойдёт вправо-вниз. Если увеличить только y — влево-вниз. Если увеличить только z — вверх, потому что высота вычитается.

| Точка карты | Проекция при scale = 1 без сдвига |
| --- | --- |
| (0, 0, 0) | (0, 0) |
| (1, 0, 0) | примерно (0,866; 0,5) |
| (0, 1, 0) | примерно (−0,866; 0,5) |
| (0, 0, 1) | (0, −1) |
| (2, 2, 5) | (0, −3) |

Центральная вершина: (2−2)×0,866 = 0; (2+2)×0,5−5 = −3. Число −3 означает положение выше начала координат на плоскости проекции. Это ещё не пиксели окна.

## Затем перевод в пиксели

```text
X = x′ × scale + offset_x
Y = y′ × scale + offset_y
```

scale меняет размер всей фигуры. offset_x и offset_y передвигают её. z_scale меняет относительную высоту перед общим масштабированием: это не то же самое, что увеличение картинки.

При z_scale = 0 рельеф исчезнет, но сетка останется изометрической. При angle = 0 формулы станут x′ = x−y и y′ = −z×z_scale: вклад x+y по вертикали исчезнет. Если при этом все высоты нулевые, сетка выродится в горизонтальную линию. Вид сверху — другая ветка формулы: x′ = x, y′ = y.

# Камера масштаб и центрирование

Camera — объект с настройками преобразования, а не физическая камера. Метод project вычисляет положение одной точки, fit подбирает настройки для всей карты.

## Как работает fit
1. Спроецировать все точки без общего масштаба и сдвига.
2. Найти min_x, max_x, min_y, max_y. Они задают ограничивающий прямоугольник.
3. Вычислить span_x = max_x−min_x и span_y = max_y−min_y.
4. Выбрать scale = 0,9×min(width/span_x, height/span_y), пропуская нулевые размеры.
5. Вычислить смещения, чтобы центр прямоугольника попал в центр окна.

Берётся минимум: более жёсткое из ограничений гарантирует, что изображение поместится и по ширине, и по высоте. Коэффициент 0,9 оставляет поля; по ограничивающей оси это 5% с каждой стороны. У другой оси поля могут быть больше.

```text
offset_x = width/2 − ((min_x+max_x)/2) × scale
offset_y = height/2 − ((min_y+max_y)/2) × scale
```

## Числовой пример для основной карты
Границы проекции: X от −3,464 до 3,464, Y от −3 до 4. Для окна 800×600 допустимые масштабы примерно 115,47 и 85,71. Выбирается 85,71×0,9 = 77,14. Смещения получаются 400 и примерно 261,43.

Вершина (2, 2, 5) имела проекцию (0, −3), а теперь находится в пикселях (400, 30). Нижняя точка по вертикали оказывается на Y = 570. Высота изображения 540 пикселей; сверху и снизу по 30 пикселей поля.

## Одна точка и масштаб колёсиком
Для одной точки обе стороны прямоугольника равны нулю. Делить на них нельзя, поэтому fit использует масштаб 1 и совмещает точку с центром окна. App рисует маленький кружок: иначе у точки без соседей не было бы видимых рёбер.

При увеличении колёсиком опорой служит текущий экранный центр модели. Масштаб умножается на factor, а смещение пересчитывается: новый offset = anchor + (старый offset−anchor)×factor. Поэтому центр модели остаётся на месте. После изменения размера окна выполняется новый fit, и ручные масштаб и сдвиг заменяются автоматическим вписыванием.

# Окно и последовательность работы приложения

## Что делает главный модуль
Сначала проверяет число аргументов, затем вызывает parse_map. Только после успешного чтения импортирует App и открывает окно. Поэтому ошибочную карту можно проверить даже там, где нет tkinter или графического экрана.

Запись if __name__ == "__main__" означает: вызвать main только при прямом запуске файла. При импорте main из теста эта ветка не выполняется. SystemExit(main()) передаёт возвращённое число операционной системе как код завершения.

## Что делает App
Конструктор создаёт камеру и окно Tk, добавляет Canvas — область рисования — и строку подсказок. Затем назначает обработчики событий: изменение окна, клавиши и мышь.

mainloop — цикл ожидания событий. Программа не заканчивается сразу после рисования: она ждёт, пока пользователь что-нибудь сделает. Обработчик — функция, которую Tk вызывает при соответствующем событии.

## Как работает draw
1. Удаляет предыдущие элементы Canvas.
2. Вычисляет экранные координаты всех точек один раз и сохраняет в словарь.
3. Для каждой точки получает правого и нижнего соседей.
4. Берёт координаты концов и вызывает _draw_edge.
5. Для одиночной точки рисует кружок.

Словарь сохраняет готовые координаты точек и исключает повторные вычисления. Метод create_line рисует линию на Canvas. При разных цветах концов она состоит из 12 коротких участков.

## Зачем after_idle
При растягивании окна события приходят очень часто. request_redraw отменяет ранее запланированное рисование и назначает новое через after_idle — когда Tk обработает текущие события. Так несколько запросов могут объединиться в одну перерисовку.

## Почему графика изолирована
Только app.py импортирует tkinter. Парсер, модель и проекция — обычные вычисления Python. Их тестам не нужен экран. Кроме того, можно заменить Tk на другую библиотеку и сохранить чтение файла и формулы.

Для N точек рёбер примерно 2N, поэтому основная работа линейная. Но Tk хранит каждый нарисованный отрезок отдельным объектом: огромные карты могут тормозить даже при хорошей асимптотике. Это ограничение выбранного учебного способа рисования.

# Цвета и градиенты

У точки может быть явный цвет из файла. Если его нет, используется цвет по высоте. В коде это выражено так:

```python
point.color or height_color(point.z, z_min, z_max)
```

Непустая строка color выбирается первой. При None вызывается функция цвета по высоте. Сама модель при этом сохраняет None: вычисленный цвет хранится отдельно в интерфейсе.

## Как смешиваются два цвета
RGB — это три независимых канала: R, G, B. В строке #RRGGBB каждый канал записан двумя шестнадцатеричными цифрами. lerp_color переводит каналы в числа, смешивает их и снова собирает строку.

```text
C = (1 − t) × A + t × B
t = 0   → начальный цвет
t = 1   → конечный цвет
t = 0,5 → середина
```

Например, между #FF0000 и #0000FF в середине красный и синий каналы примерно равны 128, зелёный равен 0. Получается #800080 — фиолетовый. Нельзя интерполировать символы строки: смешиваются числовые значения каналов.

## Цвет по высоте
Вычисляется t = (z−z_min)/(z_max−z_min). Самой низкой точке соответствует t = 0, самой высокой — 1. Палитра проходит через синий, зелёный, жёлтый и красный. Нужный промежуток палитры снова вычисляется интерполяцией.

Если все высоты равны, знаменатель нулевой. Функция возвращает первый цвет палитры, поэтому плоская карта рисуется без ошибки.

## Цвет вдоль ребра
В идеальном попиксельном варианте для шага k из n берут t = k/n. В нашей реализации библиотека рисует каждый короткий отрезок одним цветом. Ребро делится на 12 частей, цвет каждой берётся в середине её интервала. Это приближение плавного градиента, а не попиксельный алгоритм Брезенхема.

При одинаковых цветах концов достаточно одного отрезка. Обе функции расчёта цвета находятся в projection.py и проверяются тестами. Они также не зависят от Tk.

# Как устроены проверки качества

## pytest проверяет поведение
Тест — небольшой пример с известным правильным результатом. assert проверяет условие. Если оно ложно, тест не проходит.

```python
assert grid[2][2].z == 5
assert camera.project(Point(0, 0, 0)) == (0, 0)
```

pytest.raises проверяет, что ошибочный вход вызывает нужное исключение. Это успешная проверка обработки ошибки, а не поломка программы.

```python
with pytest.raises(MapFormatError):
    parse_map("maps/bad/non_numeric.fdf")
```

@pytest.mark.parametrize запускает одну функцию для нескольких наборов данных. Поэтому число тестовых случаев больше числа функций с именами test_*. В проекте получается 58 случаев, включая требуемые «7», «−3», «2,0xFF8800» и «1,0xff».

Для дробных вычислений используется pytest.approx: число с плавающей точкой может содержать небольшую погрешность. tmp_path даёт временную папку для тестовых файлов, capsys позволяет проверить напечатанные сообщения.

## mypy проверяет типы
mypy читает код и аннотации и ищет несовместимые типы. Например, если переменная ранее была целым номером строки, а затем в неё записали текст строки, строгая проверка сообщит об этом. mypy не доказывает правильность формулы — для этого нужны тесты.

## ruff проверяет код
ruff ищет неиспользуемые импорты, ошибочные конструкции и выбранные нарушения стиля. Чистый линтер не гарантирует правильный результат, поэтому используются все три инструмента.

```text
python -m pytest -q
python -m mypy --strict fdf main.py
python -m ruff check .
```

GitHub Actions выполняет эти команды на удалённом сервере после push и создания PR, когда проект опубликован. Сам файл ci.yml уже подготовлен, но результата облачного запуска пока нет.

tests/test_public.py преподавателя не был приложен. Его нельзя заменить своим одноимённым файлом и объявить совместимость подтверждённой. Если стартовый набор появится, нужно запустить именно его и при необходимости согласовать API.

# Ответы на все контрольные вопросы

## 1 Почему парсер возбуждает исключение
Парсер отвечает за чтение и проверку, а main.py — за общение с пользователем и завершение процесса. Поэтому один парсер можно использовать в окне, консоли и тестах. Исключение передаёт причину ошибки вызывающему коду.

## 2 Почему z вычитается и что меняют параметры
Экранная Y увеличивается вниз. Вычитание положительного z поднимает вершину вверх. При angle = 0 исчезает вертикальная составляющая от x+y: y′ = −z×z_scale. Плоская карта становится линией. При z_scale = 0 исчезают высоты, остаётся плоская изометрическая сетка.

## 3 Почему fit помещает карту в окно
Он находит границы всех проекций и берёт меньший из масштабов, допустимых по ширине и высоте, с запасом 10%. Затем совмещает центры. Нулевые размеры границ не участвуют в делении; для одной точки scale = 1, а сама точка оказывается в центре.

## 4 Почему только правый и нижний соседи
Так каждая связь создаётся один раз. Левого соседа текущая точка уже получила как правую связь предыдущей, верхнего — как нижнюю связь предыдущей строки. Всего для W×H получается H×(W−1)+W×(H−1) рёбер.

## 5 Почему вычислительные модули не импортируют графику
Им не нужны окно и события. Их можно проверять без экрана и переносить в другой интерфейс. Разделение уменьшает число зависимостей и делает ошибки проще для поиска.

## 6 Как вычисляется цвет пикселя
Для шага k из n берётся t = k/n, затем каждый RGB-канал вычисляется как (1−t)×A+t×B. Каналы — числовые интенсивности, а строка цвета — только способ их записи. В нашем Tk-варианте используется приближение 12 отрезками, а не вычисление каждого пикселя.

## 7 Чем PR отличается от коммита в main
Коммит сохраняет изменение в истории Git. PR — предложение влить изменения ветки в другую ветку на GitHub: там видны различия, описание, обсуждение и проверки. Прямой коммит в main не создаёт такого этапа рассмотрения. Описание PR сообщает, что изменилось и как это проверили. Локальное объединение веток не считается GitHub PR.

# Как завершить оформление GitHub

## Что уже подготовлено
В архиве есть исходники, карты, 58 тестовых случаев, README со снимком настоящего окна, конфигурация Actions, лицензия и локальная история разработки. ## Что остаётся обязательным для сдачи
Нужен публичный репозиторий fdf-python в твоём аккаунте, три настоящих влитых PR и опубликованный GitHub Release v1.0. Доступа к твоему GitHub при подготовке не было, поэтому эти действия не выполнены. Инструкция и готовые тексты описаний находятся в docs/GITHUB.md и docs/pr_*.md.

Порядок публикации: авторизоваться в GitHub CLI, создать пустой репозиторий, отправить первоначальную заготовку в удалённую main, затем по очереди открыть и влить три ветки. После успешных проверок создать релиз на удалённой main. Команды приведены в инструкции.

Не отправляй готовую локальную main первым действием: иначе изменения уже окажутся в ней и PR будут пустыми. Именно поэтому инструкция начинает удалённую main с тега scaffold. Не используй git push --all до завершения процедуры.
